# 踩坑记录

[English](pitfalls.en.md) · [返回 README](../README.md)

这些都是部署过程中真实遇到的问题。每条都写了**现象 → 原因 → 本项目的处理**。

## 代理变量

1. **“端口在听才开代理”的终端片段会失败开放**
   - 现象：开终端时代理还没起来，这个终端以及从它启动的 Claude Code，整个生命周期都直连。
   - 原因：代理端口不通时请求会**立即**报“连接被拒”，并不会卡住，所以“端口不在就不设代理”这个顾虑根本不成立，反而留下了泄漏口子。
   - 处理：`macos/shell/proxy.zsh` 无条件设置代理变量，端口不通时只打印提示。
2. **Claude Code 不读操作系统的系统代理**
   - 现象：从 GUI、IDE、计划任务或 launchd 启动时，没有代理变量就直连。
   - 处理：用托管设置（`managed-settings.json`）兜底，它的优先级最高。
3. **供应商切换工具会重写 `settings.json` 的 `env`**
   - 现象：切换模型供应商时，整块 `env` 被换掉，写在里面的代理变量没了。
   - 处理：托管设置不受这些工具影响。
4. **Node 原生 `fetch` 无视 `*_PROXY`**
   - 处理：设 `NODE_USE_ENV_PROXY=1`（Node ≥ 22.21 / 24.5）。设了之后代理断了也会失败关闭。

## macOS pf

5. **`flags S/SA` 会拦掉“别人连进来时本机的回包”**
   - 现象：隔空投送、接力、通用剪贴板、AirPlay 接收、局域网访问本机的开发服务全部失效。
   - 原因：pass 规则默认只匹配**主动外连的第一个包**；本机作为服务端回的 SYN-ACK 不匹配，掉进了 block 规则。
   - 处理：放行规则用 `flags any`。
6. **App Store 版 Tailscale 的网络扩展以用户身份运行**
   - 现象：完整模式会把它连全球中继的流量一起拦掉。
   - 处理：换成官网独立版（系统扩展以 root 运行）。注意换版本相当于一台新设备：会拿到新的 Tailscale IP，所有引用旧地址的地方都要跟着改。
7. **苹果服务会绕开系统代理直连 `17.0.0.0/8`**（QUIC 和 TCP 都有）
   - 处理：完整模式默认放行苹果网段，可以用 `--no-apple` 关掉。苹果看到你的真实 IP，与“Claude 看不到”这个目标无关。
8. **pflog 里没有 pid**
   - 现象：macOS 填了 uid，但 pid 恒为 100000，所以被拦的包没法对应到进程。
   - 处理：改用目的地址、端口和 TCP 标志位来判断（例如“从本机监听端口发出的 SYN-ACK”就是回包）。`diag_pflog.sh` 里写了这个方法。
9. **`tailscale netcheck` 在完整模式下会误报故障**：这个命令是以你的用户身份自己发 STUN 探测包的，会被拦。真实状态看 `tailscale status --json` 里的 `Health` 和 `Relay`。
10. **开机后约 1 分钟 pf 规则才加载**：这是 launchd 启动第三方守护进程的时点决定的。这段时间 Claude Code 仍被代理变量管着，代理还没起来时请求只会失败，不会直连。
11. **以 root 身份写到 `/tmp` 的文件普通用户删不掉**（粘滞位）：自动化脚本复用同名日志，可能读到上一次运行的结果。每次运行请用带时间戳的新文件名。

## 代理客户端

12. **Clash Verge Rev 的 Sidecar 模式**：内核以你的用户身份运行，所以完整模式不可用。重启时如果旧内核还占着端口，新实例会改用别的端口，系统代理也跟着变。
13. **黑名单（GFW 列表）分流模式会泄漏**：没被墙的境外域名一律直连。
14. **`GEOIP` 规则会触发本地 DNS 解析**：域名会被本地运营商的 DNS 看到。已知的境外域名请放在 `GEOIP` 之前。
15. **节点落地 IP 变了而客户端没更新**：现象是所有境外流量都失败。失败关闭保证了不会泄漏，但这种“安全地坏着”很容易被忽略，要有监测。

## Windows

16. **非交互地运行 PowerShell 脚本（经 SSH、CI 等）的四个坑**：
    - `powershell -Command -` 从标准输入读脚本时，跨行的 `if`/`for` 会被逐行拆开，后面的语句静默不执行；
    - 脚本里启动的子进程会把标准输入里剩下的脚本读走；
    - 默认 shell 是 PowerShell，cmd 的 `%TEMP%` 写法不会展开；
    - 不带 BOM 的 `.ps1` 里的中文会按 GBK 读错。

    正确做法：本地给 `.ps1` 加 UTF-8 BOM（或者只写 ASCII），scp 过去，再用 `-File <绝对路径>` 执行。
17. **托管设置要写成不带 BOM 的 UTF-8**，路径是 `%ProgramFiles%\ClaudeCode\managed-settings.json`。
18. **防火墙只能按程序过滤**：npm 版 Claude Code 是在 `node.exe` 里运行的，没法单独针对它设规则，所以先 `claude install` 换成原生版 `claude.exe`。
19. **桌面应用的后台服务常以 SYSTEM 身份运行**，不读你的用户代理。全进程封禁 Anthropic 网段那条规则能兜住它连 Anthropic 本身的流量。

## 操作习惯

20. **不要用“不通的代理”去探测 Claude Code**：刷新令牌失败后，它可能把本地登录凭证清掉，需要重新 `/login`。要看它连哪些主机，用 `tools/probe_hosts.py`，并且最好在一个丢了登录也无所谓的环境里做。
21. **不要按路径关键字模糊匹配去结束进程**：同名产品的服务（比如某个桌面应用的后台服务）会被误伤。请精确匹配可执行文件路径。
22. **`503 credential validation failed` 是服务端返回的**：本项目拦下的请求表现为“连接被拒”，拿不到任何 HTTP 状态码；本地代理出错通常是 502。
23. **出口验证不要只看状态码**：只看状态码会被连接复用骗过去（返回“204 很快”，其实走的是旧连接）。请用回显 IP 的接口验证出口，本项目用的是 Cloudflare 的 `/cdn-cgi/trace`。
