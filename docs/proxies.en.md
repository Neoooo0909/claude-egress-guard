# Per-proxy setup notes

[中文](proxies.md) · [Back to README](../README.en.md)

## Requirements for every client

1. **A local HTTP (or mixed) port** — used by `CEG_PROXY_URL` (shell), `--proxy-url` (macOS installer), `-ProxyUrl` (Windows).
2. **Claude domain rules** generated by `python3 tools/gen_proxy_rules.py --target <client>`, placed **before** any `GEOIP` / `GEOSITE,cn` DIRECT rule.
3. **A dedicated policy that contains only your fixed exit** — no `DIRECT`, no auto-selection across many nodes (a hopping exit IP is a risk signal).
4. **Unmatched traffic defaults to the proxy** (whitelist style: "domestic direct, everything else proxied"). **Do not use blacklist / GFW-list modes**: unblocked foreign domains — Claude's telemetry, for instance — go direct there.
5. **Know which account runs the proxy core** — it decides whether macOS full mode is possible.
6. **When the exit node's address changes, update every device** (node address in each client and `expected-egress.txt`).

### Who runs the core?

```bash
# macOS / Linux: what matters is the process LISTENING on the proxy port (a GUI front-end's owner is irrelevant)
lsof -nP -iTCP:7890 -sTCP:LISTEN          # look at the USER column; use your port
# VPN / packet-tunnel network extensions running as your user (they listen on no port)
ps -axo user,comm | grep -i -E 'IPNExtension|PacketTunnel|NetworkExtension' | grep -v grep
```
```powershell
# Windows
Get-CimInstance Win32_Process | Where-Object Name -match 'mihomo|clash|sing-box|xray|v2ray' |
  ForEach-Object { "$($_.Name) owner=$((Invoke-CimMethod -InputObject $_ -MethodName GetOwner).User)" }
```

| Core runs as | macOS modes | Why |
|---|---|---|
| root (system service / privileged helper) | `full` or `anthropic-only` | full mode only restricts your user; the core's upstream connections are unaffected |
| your user | `anthropic-only` only | full mode would block the core's own upstream connections → total outage (the installer checks who listens on the `--proxy-url` port and refuses if it is your user) |
| anything, on Windows | both firewall rules | Windows filters per program, not per user |

---

## mihomo / Clash family (Clash Verge Rev, ClashX Meta, FlClash, mihomo-party …)

- Rules: `gen_proxy_rules.py --target mihomo`. Remote subscriptions overwrite rules — put them into the client's "extend config / Merge / rules prepend". Prepend places them first, which is fine for Claude domains (they are not in `cn`).
- **Clash Verge Rev service mode** → core runs as root → full mode OK. Install the service from Settings or with the bundled `Contents/Resources/resources/clash-verge-service-install` (root; set `CLASH_VERGE_SERVICE_GID` to your group id, usually staff=20), then restart Clash Verge cleanly. **Sidecar mode** → core runs as you → `anthropic-only` only.
- The tray's "direct / global" modes bypass every rule. Backstops: L3① (no process, including the core, can reach Anthropic's ranges → requests fail) and L4 (the gate sees exit == real IP and blocks).
- DNS: `GEOIP` rules make the core resolve names locally. Put known foreign domains (`DOMAIN-SUFFIX`, `GEOSITE,geolocation-!cn`) before GEOIP to cut local DNS lookups.
- Restart pitfall (sidecar): after the GUI quits, the core may still hold the port; a new instance started right away falls back to another port (e.g. 7900) and moves the system proxy with it. Wait until both are gone and the port is free.

## sing-box (SFM / SFA / Hiddify / GUI.for.SingBox)

- Rules: `gen_proxy_rules.py --target singbox` → one `route.rules` entry plus a `selector` with only your fixed exit; keep `route.final` = proxy.
- DNS: use a remote (proxied) DNS server or fakeip for Claude domains so they are never resolved locally.
- TUN: `strict_route: true`. macOS clients run as a network extension — check its owner with `ps` before choosing full mode.

## xray / v2rayN (common on Windows)

- Rules: `gen_proxy_rules.py --target xray`. In v2rayN pick a "bypass mainland (whitelist)" routing set and add the rule as the **first** rule; **do not use the "blacklist" set** (delete it to avoid switching to it by accident).
- The core runs as your user → on Windows use this project's per-program rule (`windows/install.ps1`); per-user blocking is not possible there.
- Node addresses are not refreshed automatically: when the exit's IP changes, update it manually or from the subscription, otherwise nothing foreign works (the gate reports "cannot measure the exit").
- Editing config files directly: quit v2rayN before editing `guiConfigs/guiNDB.db` (it writes its in-memory copy back on exit).

## Surge for Mac

- Rules: `gen_proxy_rules.py --target surge`, `FINAL` → your proxy group.
- Surge runs as your user → `anthropic-only` only (it is the process listening on the proxy port, so the installer refuses full mode). Same for Enhanced Mode.

## Other clients (ShadowsocksX-NG, NekoRay, Hiddify, Qv2ray …)

Anything with a local HTTP port and domain-based rules works. Core running as your user → `anthropic-only` on macOS, per-program rule on Windows.

## Third-party model providers (`ANTHROPIC_BASE_URL`)

Model calls go to the provider and follow your rules. **Claude Code still sends telemetry and settings requests to Anthropic**, so the gate keeps checking the Anthropic route. The status line shows `(provider <host>)`.
